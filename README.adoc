== What is this?

A companion plugin for the {uri-later-binding}[Subscriber Later Binding] plugin of OpenSCD.
It is a background plugin with no user interface of its own.
When you subscribe or unsubscribe an input of an NR Electric device in Subscriber Later Binding, it subscribes or unsubscribes the input for the quality of the value.

Everything happens as part of the same user action, so one undo reverses all of it.

{uri-demo}[Try it out online].

== How it works

The plugin acts only on inputs of IEDs whose `manufacturer` is exactly `NRR`.
It never overwrites:

* It subscribes only inputs that have no subscription, or part of one.
* It unsubscribes only inputs that are subscribed to the data it would have subscribed them to.

In NR Electric devices the input for the quality of a value follows the input for the value.
Their internal addresses differ only in the last part, e.g. `1-A:MUGO/GOINGGIO1.SPCSO1.stVal` and `1-A:MUGO/GOINGGIO1.SPCSO1.q`.

When an input is subscribed to an FCDA, the next input is subscribed to the next FCDA if:

* the next input has the same internal address except for the last part, which is `q`, and
* the next FCDA is the same data with the data attribute `q`.

The last part of an internal address is what follows its last `.` or `/`.

== Using the plugin

. Load the plugin as a background plugin, together with the Subscriber Later Binding editor plugin.
. Open the settings of Subscriber Later Binding (the cog in either view).
.. _NR Electric companion plugin_ is listed with what it does.
It is on unless you turn it off; Subscriber Later Binding remembers the choice.
.. _Allow External Plugins_ must also be on (the default).
It lists the active companion plugins, and the settings button shows how many there are.
. Subscribe and unsubscribe as usual.
The plugin adds its subscriptions to the same action, so one undo reverses everything.

== Loading the plugin

The plugin works with {uri-shell}[`oscd-shell`] and other hosts that implement the OpenSCD plugin API.
It is a background plugin whose module's default export is the plugin class.
It needs a document, so it is listed with `requireDoc: true`.

The latest build from `main` is at {uri-ci-bundle}.
In an `oscd-shell` `plugins` object:

[source,js,subs=+attributes]
----
{
  background: [
    {
      name: '{plugin-name}',
      translations: {
        de: 'Späte Bindung des Abonnenten - NR Electric',
        pt: 'Associação Tardia de Assinante - NR Electric'
      },
      icon: 'none',
      requireDoc: true,
      src: '{uri-ci-bundle}'
    }
  ]
}
----

The package is also published to npm as `@openpowershift/oscd-background-subscriber-lb-nr`.

== Development

Build, lint, test and bundling use the shared `oscd` command from {uri-tooling}[`@omicronenergy/oscd-tooling`], through the npm scripts.

 $ npm i
 $ npm start

Then open http://localhost:8000/demo/.
The port may differ if 8000 is in use; the server prints it.

=== With a local Subscriber Later Binding plugin

The demo loads Subscriber Later Binding in this order:

. from the URL given with `?laterBinding=<url>`,
. from a linked local checkout, when served locally,
. from its deployed site.

To use a local checkout next to this one:

 $ (cd ../oscd-editor-subscriber-later-binding && npm i && npm run bundle)
 $ npm link ../oscd-editor-subscriber-later-binding
 $ npm start

Run `npm run bundle` in the later binding checkout again after changing it.
`npm link` does not change `package.json`, and a later `npm i` removes the link.

=== Companion plugins

How companion plugins work with Subscriber Later Binding is described in its {uri-later-binding-companions}[development documentation].
In short:

. When connected, and whenever Subscriber Later Binding asks, the plugin announces itself on `window` with its identity, name, description and features.
Subscriber Later Binding lists it in its settings from this, and keeps whether the user turned it off.
. After each subscription or unsubscription, Subscriber Later Binding tells companions on `window` what it did, with the identities of the companions that are turned on.
. If this plugin is among them and the input belongs to its manufacturer, it works out its edits and hands them back through `apply`.
Subscriber Later Binding applies them as part of the same undoable action.

Companions never handle the host's edit events, and have no settings of their own.

`src/companion/` is the part shared with the SEL and Siemens companion plugins.
`src/companion/protocol.ts` is a copy of the protocol in Subscriber Later Binding and must be kept identical to it.
The NR Electric rules are in `src/foundation/`.
The specs use the SEL fixture, `test/fixtures/SEL_SV_and_GOOSE.scd`, which has an NR Electric merging unit subscribing to an SEL relay.

=== Testing

 $ npm test

The specs (`*.spec.ts`) run in Chromium with Web Test Runner, with coverage thresholds.
`src/testing/later-binding.ts` stands in for Subscriber Later Binding.
It uses the same events and the same undo history as the host, so the specs check that a whole action undoes and redoes as one edit.

The plugin has no user interface, so there are no screenshot tests.
